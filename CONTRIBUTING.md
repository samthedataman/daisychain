# Contributing

Contributions should make the workflow easier to use or supply evidence about when it helps.

- Keep the skill concise; put substantial optional guidance in linked references.
- Explain the concrete failure or use case behind a change.
- Use synthetic or explicitly publishable artifacts. Exclude credentials, private conversations, customer data, and access-bearing links from files and Git history.
- Cite primary sources for research claims. Separate documented system behavior, human-team findings, and hypotheses about agent performance.
- For empirical claims, follow the [evaluation plan](docs/evaluation.md) and report costs and failures as well as successes.
- Check skill frontmatter, relative links, and whitespace before submitting a pull request. Test host-specific setup instructions if changing them, and state the tested host/version.

Changes to prompts or role names alone do not demonstrate improved outcomes.
